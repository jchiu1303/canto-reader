# Canto Reader

A Chrome (Manifest V3) popup dictionary for reading **Cantonese and Mandarin** on
ordinary web pages. Hover a Chinese word and get Jyutping, Pinyin, an English
gloss, and audio, then save words you want to study.

**Goal:** learn to read both languages while still understanding the page.

## What v1 does

- Hover (short dwell, or hold `Alt` for instant) a Chinese word to open a popup.
- Shows the headword in the page's script (Traditional or Simplified, auto-detected)
  with a cross-reference to the other script.
- Shows Jyutping (Cantonese) and Pinyin (Mandarin), with a one-click toggle for
  which reading is prominent.
- Speaker buttons use the browser's built-in TTS (`zh-HK` for Cantonese,
  `zh-CN` for Mandarin). Re-resolves voices on every play.
- Select a phrase to look it up as a whole.
- `Pin` keeps the popup open; `Save word` adds it to a local word list.
- Options page: word list, delete, CSV export (Anki-friendly), and settings.
- Toolbar button or `Alt+Shift+C` enables/disables reading mode on the current tab.

## Install (unpacked, v1)

1. `npm install`
2. `npm run build:data` (only needed once, or to refresh the dictionary)
3. `npm run verify`
4. Open `chrome://extensions`, enable **Developer mode**, click **Load unpacked**,
   and choose the `dist/` directory.
5. Open a Chinese page, click the Canto Reader toolbar icon (or `Alt+Shift+C`),
   then hover a word.

Chrome Web Store packaging is intentionally out of scope for v1.

## Privacy and security

- The dictionary is bundled **offline**. No API keys, no accounts, no network
  requests, no analytics, no telemetry, no remote code, no CDN fonts or scripts.
- Saved words and settings live only in `chrome.storage.local` on this device.
- The extension is **inert by default**: it requests only `storage`, `activeTab`
  and `scripting`, and injects its content script only on the tab you explicitly
  enable. There is no `<all_urls>` host permission.
- All page-derived text is inserted into the popup with `textContent`, never
  `innerHTML`, so a hostile page cannot inject script into the extension.
- This is a public repository: no personal names, emails, local paths, keys or
  credentials are included. See `.gitignore` for blocked patterns. GitHub secret
  scanning and push protection are enabled on the repo.

## Dictionary data

`public/data/index.tsv` is generated by `scripts/build-index.mjs` from four
redistributable open datasets. It is committed so the extension works out of the
box. To regenerate it, download the sources into `data/raw/` (gitignored) and run
`npm run build:data`:

| Source | Used for | License |
| --- | --- | --- |
| CC-CEDICT | Mandarin headwords, pinyin, glosses | CC BY-SA 4.0 |
| CC-Canto | Cantonese-specific words and colloquial glosses | CC BY-SA 3.0 |
| CC-CEDICT Cantonese readings (Pleco) | Jyutping for the whole lexicon | CC BY-SA 3.0 |
| Unihan (Unicode 18.0) | Character readings, definitions, trad/simp variants | Unicode License V3 |

See [DATA_LICENSES.md](DATA_LICENSES.md) for full attribution. The generated
index is distributed under CC BY-SA 4.0; the extension **code** is MIT.

`words.hk` is deliberately excluded from v1: its Non-Commercial Open Data License
conflicts with a public repository and with the BY-SA share-alike data.

## Development

```
npm install          # dev deps only (vite, typescript, vitest, @types/*)
npm run build:data   # regenerate public/data/ from data/raw/
npm run typecheck    # tsc --noEmit
npm test             # vitest (pure dictionary seam + real-index assertions)
npm run build        # produce dist/
npm run verify       # typecheck + test + build
npm run audit        # npm audit --audit-level=moderate
```

The single test seam is `src/shared/dictionary.ts`: pure functions
(`parseIndex`, `buildIndex`, `lookup`, `detectScript`, `formsFor`) with no DOM or
Chrome APIs. UI wiring is smoke-tested manually.

## Known limitations (v1)

- The ~14 MB index is fetched and parsed once per tab when reading mode is
  enabled (during idle, with a retry on first hover).
- Chinese word boundaries come from dictionary longest-match (authoritative), with
  Intl.Segmenter used only to skip text that has no dictionary entry; ambiguous
  over-joining of adjacent headwords is possible but rare.
- Spaced repetition, Anki sync and example sentences are deferred.
- Colloquial Cantonese gloss coverage comes from CC-Canto, not words.hk.
- Cantonese TTS depends on the voices installed on your OS (Chrome's offline
  `zh-HK` "Sin-ji" voice, or the online Google 粤語 voice).
